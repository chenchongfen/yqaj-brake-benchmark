# 字段定义（Schema）

本文件定义基准数据集各 JSON 文件的字段。**请勿沿用原始 APP 导出中的"数据说明"字段**——
那份说明是为制动数据集编写的通用模板，与本数据集的字段体系并不完全对应，且含商业内容。

---

## 1. 文件结构

每个数据集文件为单个 JSON 对象：

```json
{
  "dataset": "adversarial_curve_braking",
  "version": "1.0.0",
  "description": "…",
  "vehicle": "VehicleA (2010 B-class sedan, anonymized)",
  "n_records": 38,
  "ground_truth": { … },          // 仅对抗集有
  "records": [ { … }, { … } ]
}
```

| 顶层字段 | 类型 | 说明 |
|---|---|---|
| `dataset` | string | 数据集标识符 |
| `version` | string | 语义化版本 |
| `description` | string | 英文简介 |
| `vehicle` | string | 匿名化车型标识 |
| `n_records` | int | `records` 数组长度 |
| `ground_truth` | object | 真值标注（仅对抗集） |
| `records` | array | 逐条记录，见下 |

### ground_truth 对象（仅 `adversarial_curve_braking_38.json`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `brake_pull` | bool | `false` = 车辆不存在偏刹故障 |
| `cause` | string | 真实成因，取值 `cornering_braking` |
| `designed` | bool | `true` = 该工况为刻意构造 |
| `rationale` | string | 构造该数据集的理由 |

---

## 2. 记录字段（`records[]`）

所有记录共享同一字段集。缺失或不可计算的量以 `0` 表示（沿用 APP 约定）。

### 2.1 时间与工况

| 字段 | 单位 | 说明 |
|---|---|---|
| `CreateTime` | Unix 秒 | 记录创建时间戳。用于时序分段与同日基线对齐。**保留数据的真实采集时间，未做平移**（见 §5 时间戳策略）。 |
| `GPSSpeed` | km/h | 记录时刻车速；`-1` 表示无有效定位。**制动数据集常见为 0 或极小值。** |
| `GPSSpeedBegin` | km/h | 制动起始速度 |
| `MaxYAcceleration` | g | 纵向峰值加速度 |
| `AvgYAcceleration` | g | 纵向平均加速度 |
| `SumYAcceleration` | g | 纵向加速度累计 |

### 2.2 模态周期

| 字段 | 单位 | 说明 |
|---|---|---|
| `Duration` | s | 全周期（由极值点距离近似）。**模态频率 f = 1 / Duration。** |
| `YDuration` / `XDuration` | s | 纵向 / 侧向模态全周期 |
| `RDuration` / `PDuration` | s | 侧倾 / 俯仰模态全周期 |
| `AccelXDuration` / `AccelYDuration` / `AccelZDuration` | s | 三轴加速度通道周期 |

> ⚠️ `Duration` 为**全周期**（非半周期）。频率计算取倒数即可。

### 2.3 衰减

| 字段 | 单位 | 说明 |
|---|---|---|
| `LogDecrement` | — | **半周期**对数衰减率 δ。阻尼比 ζ = δ / π。 |

> ⚠️ 注意是**半周期**衰减率。若按整周期换算需 ×2。

### 2.4 六自由度幅值

| 字段 | 单位 | 含义 |
|---|---|---|
| `YMM` | mm | 纵向（行驶方向）模态响应幅值 |
| `XMM` | mm | 侧向幅值 |
| `ZMM` | mm | 垂向幅值 |
| `RollMM` | mm | **侧倾**幅值 |
| `PitchMM` | mm | 俯仰幅值 |
| `YawMM` | mm | **横摆**幅值 |

> 坐标约定：**Y = 行驶方向，X = 侧向。**
> 偏刹检测的核心量是 `YawMM`（横摆）；`RollMM` 是区分"转弯"的关键独立通道。

### 2.5 回弹次数（半周期计数）

| 字段 | 说明 |
|---|---|
| `SpringbackNumAccelX` / `Y` / `Z` | 三轴加速度通道回弹次数 |
| `SpringbackNumRoll` / `Pitch` / `Yaw` | 侧倾 / 俯仰 / 横摆通道回弹次数 |

> ⚠️ **回弹次数为半周期值（1 个过零点）**，整周期数 = 该值 ÷ 2。
> 由于检测方法的原因，出现**奇数**半周期值不属于错误。

### 2.6 预留/辅助字段

`HAccelX` / `HAccelY` / `HAccelZ`、`HRoll` / `HPitch` / `HYaw`：横向加速度与姿态角的
辅助量，供复现原始处理链使用。

---

## 3. 派生量定义（基准判据使用）

| 派生量 | 定义 | 说明 |
|---|---|---|
| 模态频率 | `f = 1 / Duration` | 单位 Hz |
| 阻尼比 | `ζ = LogDecrement / π` | 无量纲 |
| 横摆-纵向比 | `YWR = YawMM / YMM` | 归一化制动力不对称度 |
| 侧倾-纵向比 | `RollMM / YMM` | 转弯混杂因子 |

`YMM = 0` 时派生量不可计算，应在统计中剔除并记录剔除数。

---

## 4. 数据质量与剔除

参考该项目既有经验，建议在分析前剔除：

- 幅值全部 `< 1 mm` 的记录（低于噪声线）；
- `LogDecrement ≤ 0` 的记录（物理上不可能）；
- 明显野值（若存在）：如某自由度幅值远超同批量级，通常是手机移动造成的伪记录。

**本仓库三个数据集均已按上述口径做过基本清洗**，可直接使用。若你的处理链另有
过滤规则，请在报告中说明，以便结果可比。

---

## 5. 时间戳策略

本仓库**保留 `CreateTime` 的真实采集时间，不做平移**（决策日期 2026-10-16）。

| 数据集 | 时间覆盖 |
|---|---|
| `adversarial_curve_braking_38.json` | 2026-09-11 11:46:23 – 11:51:48 |
| `same_day_baseline.json` | 2026-09-11 11:03:23 – 21:35:27 |
| `history_baseline_1042.json` | 2025-05-16 – 2026-10-03（约 504 天） |

**为什么保留而不平移：**

1. **分析必需**：同日基线分析（对抗集 vs 同车同日其他时段）必须依赖真实时间对齐；
   平移会破坏这一核心分析路径，也会使"时间聚集特征"这一证据链无法复现。
2. **隐私风险可控**：数据集不含 GPS 坐标、不含任何个人标识字段；保留时间戳不引入
   可识别的个人/车辆信息。
3. **透明度**：时间覆盖已公开，使用方可据此判断数据的时序结构。

若下游使用方出于自身场景需要匿名化时间，可自行施加一个常数偏移（如 -N 天），
但**须在自身报告中声明**，因为任何偏移都会改变同日基线的构成。
