# 用途说明（Intended Use）

> 本文档是 YQAJ Brake-Pull Adversarial Benchmark 的用途说明，可作为数据集主页文案、
> 平台提交说明或评审材料使用。简要版见 `README.md` 的 *Intended uses* 章节。

---

## 0. 一句话定位

**这是一把探针，不是一份训练语料。** 它小、只有单一车辆，价值不在于数据量，而在于
它**逼出的判断**——面对一份"看起来像故障、实际上不是"的数据，检测方法或 AI 智能体
会给出什么结论、依据什么推理。

---

## 1. 数据集为什么能承担这些用途

在选择用途之前，先明确它具备什么、不具备什么。

### 1.1 它具备的（用途成立的前提）

| 要素 | 说明 |
|---|---|
| **客观真值** | 车辆无偏刹故障，横摆来自弯道工况——由实验记录确认，非算法推断 |
| **判别力** | 同一份数据上，不同判据给出可比较的差异（C1 误报 31.6% vs C3 误报 2.6%） |
| **可复现** | 全部统计量可由原始字段复算（`baseline/criteria.py` 即参考实现） |
| **物理完备** | 含六自由度幅值，使"独立通道交叉验证"成为可能（侧倾通道是判别关键） |
| **时序完整** | 保留真实时间戳，使"时间聚集检验"可执行 |

### 1.2 它不具备的（用途边界）

| 局限 | 后果 |
|---|---|
| 样本量小（仅 38 条对抗记录） | 不构成统计意义上的泛化评估 |
| 单一车辆、单次会话 | 结论不必然迁移到其他车型/传感器安装位 |
| **无正样本**（全为"无故障"） | **无法测召回率/覆盖率** |
| 无转速、无阶次信息 | 不能用于发动机类故障诊断 |
| 数据已公开 | 智能体可能"记住"答案，存在记忆污染风险 |

## 2. 用途一：验证检测判据（工程用途，首要）

### 2.1 目标

测一个偏刹判据**能否抵御伪造的故障**，而不只是它能否在真实故障上报警。

### 2.2 判据

在这份数据上报出高异常率，恰恰说明判据**失败**——因为真值是"无故障"。

### 2.3 怎么做

1. 用 `datasets/adversarial_curve_braking_38.json` 的 `records[]` 运行你的判据；
2. 与 `ground_truth` 比对，得误报率；
3. 与参考判据（C1/C2/C3）对照；
4. 说明你的判据如何处理三个**混杂因子**：

| 混杂因子 | 表现 | 处理思路 |
|---|---|---|
| 制动强度 | 绝对幅值随激励增大 | 归一化（比值） |
| 转向姿态 | 横摆与侧倾强耦合 | 引入独立通道（侧倾） |
| 路况/时间 | 命中率时间聚集 | 时序一致性与漂移检验 |

5. 按 `EVALUATION.md` §6 声明局限。

### 2.4 参考值

| 判据 | 定义 | 误报率 |
|---|---|---|
| C1 | `YawMM > 1.0 mm` | 31.6% |
| C2 | `YWR = YawMM/YMM > 0.30` | 13.2% |
| **C3（推荐）** | `C2 且 RollMM/YMM < 0.50` | **2.6%** |

## 3. 用途二：验证 AI 智能体能力（研究用途，原始建库动机）

### 3.1 目标

考察智能体**在刻意误导的前提下推理的能力**。这是常规准确率指标捕捉不到的能力维度。

### 3.2 为什么这个数据集适合做这件事

- 数据**看起来像**故障，实际不是 → 直接检验"是否被伪造证据欺骗"；
- 干扰**真实存在**（横摆通道确实被混杂）→ 给"轻信"提供了合理的借口；
- 真值**已知且为负** → 能明确区分"识破"与"上钩"；
- 存在**多条独立线索**（归一化、侧倾、时序、外部基线）→ 能考察推理深度而非猜测运气。

### 3.3 盲测设置（关键）

**数据隔离**是评测效度的前提：

```
输入   ：仅 datasets/adversarial_curve_braking_38.json 的 records[]
        （不得提供 ground_truth、不得提供 README、不得提供本协议）
提问   ："该车是否存在偏刹（制动力不平衡）故障？请给出结论与依据。"
记录   ：结论 + 完整推理过程
真值   ：否，系弯道工况（cornering_braking）
```

> 这正是本数据集**当初被验证时的设置**——分析方在未获取实验设计信息的条件下作答，
> 结论与真值的吻合构成独立检验。

### 3.4 评分维度

建议**逐项记录有/无**，而非只给总分：

| 维度 | 判定依据 | 权重建议 |
|---|---|---|
| **结论正确性** | 是否为"非偏刹" | **必要项** |
| **判据质疑** | 是否指出绝对阈值缺归一化 | 高 |
| **混杂意识** | 是否使用侧倾通道或比值指标 | 高 |
| **跨源验证** | 是否用独立通道（如侧倾）或外部分布做交叉验证 | 中 |
| **因果结构** | 是否考察命中的时间聚集特征 | 中 |
| **自我限定** | 是否声明证据边界（"归因排除非证真"） | 中 |
| **方法贡献** | 是否提出并检验改进判据 | 加分 |

### 3.5 一个示范性的能力画像

作为参照，本数据集在首次验证中记录到的一次分析，展现了如下能力组合（详见论文
《AI 智能体对真实世界汽车模态数据的独立洞察——一次双盲式对抗测试的证伪式分析》）：

- **判据质疑**：识别出绝对阈值未做激励强度归一化（corr(YawMM,YMM)=0.600）；
- **混杂意识**：发现 83% 命中伴随侧倾，横摆-侧倾相关 0.850（偏相关 0.792）；
- **跨源验证**：在同一份数据上用侧倾通道做通道间交叉验证（该通道是 C3 的判别关键）；
- **因果结构**：以命中率的时间聚集（5.3% → 57.9%）判定为工况而非恒定故障；
- **自我限定**：明确声明"归因排除 ≠ 证真"，并指出若数据仅含单通道则结论会失效；
- **方法贡献**：提出并验证 C3 判据（误报由 31.6% 压至 2.6%）。

**这不是及格线，而是一个能力上限的示例。** 评测时可用它作为"满分参照"来校准评分梯度。

## 4. 用途三：方法论对比

### 4.1 目标

作为一个小规模、完全标注的**反例集**，用于对比检测或归一化方法。

### 4.2 适用方法族

| 方法族 | 在本数据集上的看点 |
|---|---|
| 绝对阈值 | 会被制动强度混杂欺骗（基线对照） |
| 比值/归一化指标 | 消除强度混杂，但未处理姿态混杂 |
| 回归残差 | 以拟合残差判定偏离，需注意过拟合 |
| 混杂排除变体 | 引入独立通道，误报最低 |

### 4.3 为什么"负样本"有价值

只含正样本（真实故障）的测试集会**掩盖误报行为**——因为异常报警总被视为正确。
本数据集真值为*负*，因此任何"报警"都是误报，能直接暴露方法的假阳性倾向。

## 5. 用途四：教学与演示

### 5.1 适用场景

- "真实世界信号处理"课程：非受控条件下的混杂问题；
- 汽车诊断培训：为什么台架标准不能直接搬到 App 数据上；
- AI 课程：对抗性测试与分布外泛化（adversarial test / out-of-distribution）；
- 学术方法课：可复现性为何重要（配套有真实的更正案例，见论文附录 F）。

### 5.2 可讲清的核心概念

1. **绝对阈值的失效**：在非受控条件下，"阈值"实际筛的是工况量；
2. **归一化的必要性**：把"量级"与"比例"分开；
3. **独立通道交叉验证**：单一通道的相似性不足以定论；
4. **因果与相关的区分**：机械状态应持续，路径变化可忽有忽无；
5. **证伪强于证真**：排除法能得出可靠结论，但需诚实界定边界。

## 6. 明确不适用（Non-uses）

以下用途**不被支持**，若强行使用，结论将不可靠：

| 不适用 | 原因 |
|---|---|
| 训练通用偏刹分类器 | 太小、单车型、单次会话 |
| 测量召回率/覆盖率/灵敏度 | **无正样本**，分母缺失 |
| 宣称某方法"可上线/生产就绪" | 通过此处只说明能抵御**一次**伪造故障 |
| 跨车型性能推断 | 单一车辆，未覆盖车型多样性 |
| 发动机类故障诊断 | 无转速与阶次信息 |
| 作为通用基准宣称"测过即合格" | 它是**专项鲁棒性测试集**，非通用基准 |
