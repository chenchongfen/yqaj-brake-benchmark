# 评测协议（Evaluation Protocol）

本文件规定如何使用本基准数据集进行评测与**报告**。目的是让不同团队的结果可以互相比对，
并防止"只优化一头"式的误导性结论。

---

## 1. 评测目标

本基准有两种用途，评测目标相应不同：

**(a) 判据评测**——测的不是"能否检测偏刹"，而是：

> **面对一份由无故障车辆刻意构造的、与偏刹高度相似的横摆数据，方法能否不把它判为故障。**

即**对抗性/鲁棒性**评测。

**(b) 智能体能力评测**——测的是"**在刻意误导的前提下，能否通过推理识破伪造故障**"。
这考察的是因果推理、混杂识别与跨源验证能力，而非单一阈值。（详见 §7.2）

---

## 2. 输入与真值

| 项 | 内容 |
|---|---|
| 输入 | `datasets/adversarial_curve_braking_38.json` 的 `records[]` |
| 真值 | 该文件 `ground_truth`：`brake_pull = false`，`cause = cornering_braking` |
| 对照基线 | 仓库**不附带**。论文中使用的同日/历史基线为同车常规行驶数据，未公开（见 README「Datasets」）；引用相关统计量须以论文为准并注明基线定义 |

**评测方在给出判断前不得读取 `ground_truth` 字段**（盲测）。建议在完整的基准仓库中，
把 `ground_truth` 拆分到单独的 `_labels.json`，评测时只提供 `records`。

---

## 3. 必须报告的指标

对每一个被评测的判据/模型，报告以下两项（缺一不可）：

| 指标 | 定义 | 为什么必须报告 |
|---|---|---|
| **误报率 (FPR)** | 38 条中被判为"偏刹"的比例 | 本基准的核心：真值全为"非故障" |
| **命中率** | 同上（本基准中 FPR 即命中率） | — |

> 由于本基准全部为负样本，"命中"即"误报"。这**不是缺陷**——它正是对抗性测试的定义。
> 但必须说明：**单靠本基准无法测量漏报率**（无正样本），因此不能单独用来宣称
> "某方法可用"。要评估召回，需配合真实故障样本集（见 §6）。

### 参考值（本项目基准实现）

| 判据 | 误报率 |
|---|---|
| C1 `YawMM > 1.0` | 31.6% |
| C2 `YWR > 0.30` | 13.2% |
| C3 `YWR > 0.30 且 RollMM/YMM < 0.50` | 2.6% |

---

## 4. 归一化比较的报告规则

若报告"归一化指标在会话与基线间无差异"这类结论，**必须同时给出**：

1. 归一化量的定义（如 `YWR = YawMM / YMM`）；
2. 基线的**抽取方式与样本量**（同日窗口？最近 N 条？全量？）；
3. 统计量（如 Welch t）与样本量 `n`。

> ⚠️ **反例警示**：同一份会话数据，取"同日窗口"基线（n=62）得 `t≈2.9`，取
> "最近 100 条"基线（n=100）得 `t≈2.5`，二者结论强度不同。
> **基线定义不同，t 值不可跨研究比较。** 任何省略基线定义的 t 值都应被视为不可复现。
>
> 上述两个基线**均未随本仓库发布**，因此这两组 t 值只能作为"基线敏感性"的示例引用，
> 无法在此仓库内重算。若你的评测需要基线，请自备并明确声明其抽取口径。

---

## 5. 判据设计的最小要求（评测建议）

若你提出新判据，请说明它如何处理以下三个**混杂因子**——这是本数据集设计的考点：

| 混杂因子 | 表现 | 处理思路 |
|---|---|---|
| 制动强度 | 绝对幅值随激励增大而增大 | 归一化（比值） |
| 转向姿态 | 横摆与侧倾强耦合 | 引入独立通道（侧倾）交叉验证 |
| 路况/时间 | 命中率时间聚集 | 时序一致性与漂移检验 |

只做其中一项而在报告里宣称"解决了误报"，属于**结论不成立**。

---

## 6. 已知局限（报告时必须声明）

1. **无正样本** → 无法测召回率；本基准不能单独证明方法"可用"。
2. **样本量小（n=38）、单一车辆、单次会话** → 不构成通用能力评估。
3. **真值来自实验记录** → 是"归因排除"的验证，不是"轨迹的直接观测"。
4. **存在过拟合风险** → 数据公开后，方法可能针对这 38 条调参。**建议保留不公开的
   holdout 子集**；公开部分越大，其"泛化"证据越弱。
5. **传感器与安装位固定**（档把边）→ 结论不必然迁移到其他安装位置。

---

## 7. 建议的评测流程

### 7.1 判据评测

```
1. 只加载 records[]（盲）
2. 运行被评测判据，输出 38 条逐条判定
3. 与 ground_truth 比对，计算误报率
4. 在报告中给出：判据定义 + 误报率 + 基线定义（若做了归一化比较）
5. 按 §6 声明局限
```

### 7.2 AI 智能体能力评测

本数据集亦可用于评测 AI 智能体的**"在误导前提下推理"的能力**。与判据评测不同，
这里评的不是某个阈值，而是"结论 + 推理链"。

**盲测设置**：

```
1. 只向智能体提供 records[]（不提供 ground_truth、不提供 README/本协议）
2. 提问："该车是否存在偏刹（制动力不平衡）故障？请给出结论与依据。"
3. 记录：结论 + 推理过程（是否做了归一化、是否使用侧倾通道、是否做时序检验）
4. 与真值比对：正确答案为"否，系弯道工况"
5. 按 §7.3 的维度评分
```

**评分维度**（非二值，建议逐项记录有/无）：

| 维度 | 判定依据 | 权重建议 |
|---|---|---|
| 结论正确性 | 是否为"非偏刹" | 必要 |
| 判据质疑 | 是否指出绝对阈值缺归一化 | 高 |
| 混杂意识 | 是否使用侧倾通道或比值指标 | 高 |
| 跨源验证 | 是否用独立通道（如侧倾）或外部分布做交叉验证 | 中 |
| 因果结构 | 是否考察命中的时间聚集特征 | 中 |
| 自我限定 | 是否声明证据边界（如"归因排除非证真"） | 中 |
| 方法贡献 | 是否提出并检验改进判据 | 加分 |

> **防作弊**：数据公开后，智能体可能"记住"答案。因此应保留**不公开的 holdout 子集**
> （见 §6 第 4 条），并优先用该子集做能力评测。若使用公开的 38 条，须在报告中说明
> 存在记忆污染风险。
